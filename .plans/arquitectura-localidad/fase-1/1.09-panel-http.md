# 1.09 Test del panel HTTP

**Objetivo:** fijar el comportamiento del servidor del panel: estáticos, API, SSE y restricciones.

**Lee:** `tap.py`, solo la clase `Handler`. `tests/replay/scenario.py` (firmas), `tests/replay/adapter.py`, `tests/replay/builders.py` (firmas).

**Puedes tocar (nuevo):** `tests/test_dashboard.py`.

## Pasos

Crea `tests/test_dashboard.py` con un `unittest.TestCase`.

**`setUp`:**
1. Ejecuta `run` con 2 pasos: `W1` (`t=0`) y `W2` (`t=60`), ambos con host `api.anthropic.com`, ruta `/v1/messages`, estado 200;
   cuerpos `claude_body("claude-opus-5-5", "W", 1)` y `claude_body("claude-opus-5-5", "W", 2)`;
   trozos `anthropic_sse(0, 3000, 20)` y `anthropic_sse(3000, 200, 20)`; `expect` `COLD` y `HIT`.
2. Crea `ThreadingHTTPServer(("127.0.0.1", 0), adapter.handler())` con `daemon_threads = True`. El puerto 0 pide uno libre: léelo de `server.server_address[1]`.
3. Arranca `serve_forever` en un hilo `daemon`. Con `addCleanup`, registra `server.shutdown()` y `server.server_close()`.

Las peticiones se hacen con `http.client.HTTPConnection("127.0.0.1", <puerto>, timeout=5)`.

**Tests** (uno por fila):

| Test | Petición | Se comprueba |
| --- | --- | --- |
| índice | `GET /` | 200; `Content-Type` empieza por `text/html`; el cuerpo contiene `<title>LLM cache tap</title>`; `Cache-Control` es `no-store` |
| estático | `GET /app.js` | 200; `Content-Type` empieza por `text/javascript` |
| fuente | `GET /fonts/ibm-plex-mono-latin-400-normal.woff2` | 200; `Content-Type` es `font/woff2`; `Cache-Control` es `max-age=86400` |
| registro | `GET /api/record/2` | 200; JSON con `id` 2, `verdict` `HIT`, con la clave `segs` y sin ninguna clave que empiece por `_` |
| cuerpo | `GET /api/body/1` | 200; el cuerpo es JSON y su `model` es `claude-opus-5-5` |
| registro inexistente | `GET /api/record/99` | 404 |
| fuera de `ui/` | `GET /../tap.py` | 404 |
| extensión no servida | `GET /fonts/OFL.txt` | 404 |
| host ajeno | `GET /` con cabecera `Host: evil.example` | 403 |
| ruta POST desconocida | `POST /api/otra` | 404 |
| eventos | `GET /events` | 200; `Content-Type` es `text/event-stream`; la primera línea leída empieza por `data: `; su JSON tiene `type` `snapshot`, `recs` con 2 elementos y `ttl` 300. Después de leer esa línea, cierra la conexión |
| limpiar | antes: `adapter.subscribe()`. Petición `POST /api/clear` | 200; `adapter.records()` queda vacío; `adapter.body_ids()` queda vacío; la cola recibe `{"type": "clear"}` |

En el test de eventos lee una sola línea con `readline()` sobre la respuesta; no uses `read()`, que no termina nunca porque el servidor mantiene la conexión abierta.

Para enviar la cabecera `Host` ajena usa `putrequest("GET", "/", skip_host=True)`, `putheader("Host", "evil.example")` y `endheaders()`.

- TESTS completo acaba en `OK`.
- El test no usa los puertos 8899 ni 8900.
