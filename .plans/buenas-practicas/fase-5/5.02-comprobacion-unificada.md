# 5.02 Comando unificado y CI

**Objetivo:** los controles de calidad se ejecutan con un comando local y automáticamente en GitHub.

**Lee:** `tests/ui/check.mjs`; `tests/replay/serve.py`; `requirements-dev.txt`; `pyproject.toml`; `start.sh` (solo referencia de instalación); `tests/test_dependencies.py`.

**Puedes tocar:** `scripts/check.py` (nuevo), `.github/workflows/check.yml` (nuevo), `requirements-ci.txt` (nuevo), `tests/test_check.py` (nuevo).

## Pasos

1. Crea check.py con subprocess.run(check=True), cwd obtenido de su propia ruta, sin shell=True. Orden: Ruff lint, Ruff format check, mypy, unittest, JS. `--full` añade UI al final; cualquier fallo devuelve código no cero y no imprime éxito global.
2. Para Python usa sys.executable, para Node `node`. Verifica existencia de venv/bin/python para el runner UI y explica el requisito si falta. No arranques proxy real ni escribas logs reales.
3. Crea requirements-ci con `mitmproxy==12.2.3` y una referencia a requirements-dev.txt. Se comprobó que 12.2.3 declara Python >=3.12. Es un entorno con dependencias directas fijadas, no un lock completo de transitivas; no copies pip freeze del venv personal ni rutas editables.
4. Workflow en ubuntu-latest, Python 3.12 y Node 24, checkout y setup-python/setup-node; crea venv, instala requirements-ci y ejecuta `venv/bin/python scripts/check.py --full`. Encuentra Chrome con shutil.which en un paso Python y exporta CHROME_BIN; falla claramente si no existe. El navegador usa perfil temporal propio.
5. Añade test del runner con subprocess mock: orden y argumentos exactos, propagación de error y --full. No necesita herramientas reales ni red.

## Verificación

- `venv/bin/python scripts/check.py --full`: todos los pasos pasan y código 0.
- TESTS incluye test_check con cero fallos.
- Revisa sintaxis del YAML con parser YAML ya incluido por mitmproxy; ejecutar un workflow remoto requiere publicar cambios y no forma parte de esta tarea.
