# 3.02 Detalle HTTP sin carreras ni errores silenciosos

**Objetivo:** las respuestas antiguas no repintan una selección nueva y los fallos tienen explicación visible.

**Lee:** `ui/detail.js` completo; `ui/status.js`; `ui/stream.js` (invalidación); `tests/ui/check.mjs` (js, detailHas, C4/C11); `contratos.md` (Expulsión y Diagnósticos).

**Puedes tocar:** `ui/detail.js`, `tests/ui/check.mjs`.

## Pasos

1. Introduce un contador de generación de detalle y AbortController para record/body. showDetail aborta la carga de record anterior; closeDetail/resetDetailCache invalidan generaciones y abortan ambos requests.
2. Comprueba generación y selected después de cada await, incluidos res.json/res.text. No uses únicamente la igualdad de ID: dos cargas del mismo ID pueden terminar invertidas.
3. Para body conserva el nodo host solo si sigue conectado y corresponde a la generación vigente; si no, abandona. Evita reutilizar el cuerpo de una sesión limpiada cuyos IDs se repitan.
4. Captura AbortError sin aviso; 404 del record cierra detalle y muestra «La petición ya no está en memoria.»; 404 del body mantiene el texto existente. Red/5xx/JSON inválido muestra mensaje de error/reintento en el panel mediante textContent.
5. Captura fallo del portapapeles y muestra «No se pudo copiar.» en el botón; restablece etiqueta sin promesas rechazadas.
6. Añade checks con promesas controladas de fetch: A/B terminado B/A; dos actualizaciones del mismo ID; clear mientras res.json está pendiente; body 404, rechazo red y clipboard rechazado. Restaura API tras cada caso.

## Verificación

- UI: todos los checks pasan; prevalece la selección/generación vigente y no hay rechazos sin manejar.
- TESTS: `OK`.
