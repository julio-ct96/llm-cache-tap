# 3.01 Diagnósticos visibles de conexión y acciones

**Objetivo:** limpiar o recibir un evento inválido no produce rechazos sin manejar ni estados falsos de éxito.

**Lee:** `ui/app.js` (clear); `ui/stream.js`; `ui/help.js`; `ui/index.html`; `ui/format.js`; `tests/ui/check.mjs` (`connect`, `check`, C1/C14); `contratos.md` (Diagnósticos).

**Puedes tocar:** `ui/status.js` (nuevo), `ui/events.js` (nuevo), `ui/app.js`, `ui/stream.js`, `ui/help.js`, `ui/index.html`, `tests/ui/check.mjs`, `tests/ui/unit/events.test.mjs` (nuevo).

## Pasos

1. Añade un `<p id='action-status' role='status' aria-live='polite' hidden>` en toolbar. status.js exporta `showStatus(message)` y `clearStatus()` usando textContent/hidden.
2. Clear espera fetch, comprueba res.ok, deshabilita el botón mientras dura y lo restaura en finally. Error visible «No se pudieron limpiar las peticiones. Inténtalo de nuevo.»; no borra state local sin evento del servidor.
3. Exporta `parseEvent(data)` en events.js, un módulo puro sin imports de DOM; stream lo importa. Parsea JSON y comprueba variantes/IDs positivos enteros, snapshot array de registros con IDs, ttl positivo y max_records entero positivo si existe. Valida evicted_ids/ids como arrays de IDs; rechaza tipos desconocidos. No exijas campos ausentes legítimamente en un registro pending.
4. Si el SSE es inválido, muestra «Se recibió un evento inválido; reconectando.», cierra source y crea una única reconexión con setTimeout de 1000 ms. Devuelve desde connect una función de cierre que cancela esa reconexión; conserva el retry nativo para errores de transporte.
5. Help comprueba HTTP/JSON/forma de tablas; error visible «No se pudo cargar la referencia de ayuda.» en vez de un fallo silencioso. Conserva fallback silencioso de localStorage: es opcional y no es un error de la operación principal.
6. En los checks, inyecta fallos con mock temporal de window.fetch y prueba el parser por import. Restaura mocks; no envíes requests reales que contaminen C1 con 500 esperados.

## Verificación

- JS: evento inválido rechazado y datos válidos aceptados; cero fallos.
- UI: incluye clear rechazado/conexión inválida/help fallida; todos los checks pasan y cero rechazos sin manejar.
- TESTS: `OK`.
