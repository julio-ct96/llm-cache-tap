# 2.07 Suscriptores SSE y consumidores lentos

**Objetivo:** todas las modificaciones de clientes respetan el lock y las colas no crecen indefinidamente.

**Lee:** `cachetap/store.py` (`publish`, `push`, `clear` y contrato LOCK); `cachetap/dashboard.py` (`_events`); `tests/replay/adapter.py` (`subscribe`, `reset`); `tests/replay/scenario.py` (`run`); `tests/test_store.py`; `tests/test_dashboard.py`; `contratos.md` (Clientes SSE).

**Puedes tocar:** `cachetap/config.py`, `cachetap/store.py`, `cachetap/dashboard.py`, `tests/replay/adapter.py`, `tests/test_store.py`, `tests/test_dashboard.py`, `tests/replay/serve.py`.

## Pasos

1. Añade MAX_CLIENT_EVENTS. Introduce `subscribe()`/`unsubscribe(q)` en store; necesitan LOCK y crean queue con maxsize. Snapshot y subscribe siguen dentro del mismo bloque en dashboard.
2. Usa put_nowait en publish. Ante queue.Full vacía y encola disconnect; retira la cola de CLIENTS para no publicar más. Itera sobre copia; protege todo con el lock externo.
3. En `_events`, al consumir disconnect retorna sin enviarlo. Finalmente llama unsubscribe bajo LOCK, tolerando que ya se retiró. No mantengas LOCK en readline/write/flush/get.
4. Haz que el adaptador use esas funciones bajo LOCK. Actualiza tests que llaman publish/push/clear directamente para adquirirlo.
5. Añade prueba concurrente con productor y altas/bajas sincronizados por barrera; captura excepciones de threads y usa join con deadline.
6. En serve.py usa una subclase local de ThreadingHTTPServer cuyo server_bind invoque socketserver.TCPServer.server_bind y asigne server_name='localhost' y server_port desde server_address. Así evita socket.getfqdn, cuya resolución DNS inversa se comprobó que bloquea el arranque del fixture. Mantén loopback y puertos de prueba. Prueba este binding con socket.getfqdn mock que falle si se invoca, cerrando el servidor al terminar.

| Caso nuevo | Resultado |
| --- | --- |
| Cola de capacidad 2, tres publicaciones sin consumir | Solo disconnect pendiente; cliente retirado |
| Cliente rápido junto al lento | Conserva todos los eventos; productor no bloquea |
| Unsubscribe repetido | Idempotente |
| Reconexión HTTP | Snapshot de registros actuales |
| Replay existente | 131 eventos completos, sin disconnect |
