# 2.05 Acotar el estado del navegador

**Objetivo:** el navegador conserva solo registros retenidos y libera el detalle expulsado.

**Lee:** `ui/state.js`; `ui/stream.js`; `ui/detail.js` (`body`, `showDetail`, `closeDetail`); `ui/list.js` (`render`, `syncFilters`); `tests/ui/check.mjs`; `contratos.md` (Expulsión).

**Puedes tocar:** `ui/state.js`, `ui/stream.js`, `ui/detail.js`, `tests/ui/unit/retention.test.mjs` (nuevo), `tests/ui/check.mjs`.

## Pasos

1. Añade `maxRecords:300` a state y exporta `applyEvent(ev)`: modifica únicamente el estado de datos; devuelve si la selección dejó de ser válida. Soporta snapshot, clear, record con expulsados y evict según contrato.
2. En stream usa applyEvent y cierra el detalle si indica invalidación. Mantén la actualización del detalle seleccionado y sus timers para eventos válidos.
3. En closeDetail libera body, trees y copyable. Exporta `resetDetailCache()` e introduce una generación que invalida cuerpo y requests pendientes al cambiar snapshot/clear; úsalo desde stream aunque el ID seleccionado siga existiendo en el nuevo snapshot. Comprueba generación tras los awaits de record/body para que ningún request anterior restaure el detalle expulsado. La tarea 3.02 completará cancelación, errores y carreras entre requests del mismo ID.
4. Añade tests JS de estado y un check de navegador que invoque applyEvent mediante import dinámico, compruebe expulsión de selección y renderice; ejecuta este caso después de los checks actuales para no cambiar sus 44 filas.

| Caso nuevo | Resultado |
| --- | --- |
| Snapshot límite 2 e IDs 1,2,3 | IDs 2,3 |
| Actualizaciones repetidas del mismo ID | Tamaño estable |
| Evento 4 con expulsado 2 | IDs 3,4 |
| Snapshot nuevo/clear | Sin registros anteriores ni selección obsoleta |
| Evict de selección | Detalle oculto, cuerpo liberado |
| Eventos sin expulsados | Comportamiento visible actual |

## Verificación

- JS: cero fallos.
- TESTS y UI pasan; sin imports JS rotos ni cambios en golden.
