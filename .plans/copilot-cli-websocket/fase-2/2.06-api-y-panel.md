# 2.06 Verificar que la captura llega a la API y al panel

**Objetivo:** Probar la entrega de registros WebSocket a la interfaz existente, sin rediseñarla.

**Lee:** `cachetap/dashboard.py`: GET record/body/events; `tests/test_dashboard.py`: servidor con puerto 0 y lectura SSE; `tests/test_websocket_hooks.py`: generación del fixture; `tests/ui/check.mjs`: helper js, check C32 y bloque final de pruebas sintéticas; `protocolo.md`: caso y campos opcionales.

**Puedes tocar:** `tests/test_websocket_dashboard.py` (nuevo), `tests/ui/check.mjs`.

## Pasos

1. Añade una suite HTTP local con su propio estado temporal y servidor en puerto 0. Alimenta el caso sintético por los hooks reales mediante `tests.test_websocket_hooks.play_fixture()`, sin ejecutar su TestCase ni hacer llamadas externas. Ese helper devuelve `(flow, rid)` y no resetea store: el setup de esta suite redirige el log y prepara el estado antes de llamarlo.
2. Comprueba el contrato público:

   | Endpoint | Resultado esperado |
   | --- | --- |
   | `/api/record/<id>` | Registro done, `transport=websocket`, modelo, PARTIAL, uso y coste del fixture; ninguna clave interna |
   | `/api/body/<id>` | Objeto de inferencia normalizado; ni type ni headers raíz ni sentinel |
   | Snapshot de `/events` | Una fila ligera, sin raw_usage/segs ni sentinel; convs con priced=1 |
   | Actualización SSE de terminal | Un evento final; mismo ID y total que el detalle |

3. No cambies `tests/test_dashboard.py`: contiene trabajo previo ajeno y no hace falta tocarlo para esta cobertura.
4. Añade al final de las pruebas sintéticas del navegador un check `C34` que inyecte, a través de applyEvent, un registro artificial con los valores expected del fixture, status 101 y transport websocket. Mockea solo las respuestas de detalle/cuerpo de ese ID. Restaura fetch, estado y selección en finally, como hacen las pruebas existentes.
5. En C34 comprueba una fila para ese ID, modelo visible, detalle con PARTIAL, tarifa Copilot, texto Hola mundo y tokens de caché correctos. Comprueba además que abrir el cuerpo no muestra el sentinel ni el sobre headers. Usa las utilidades existentes de espera, no pausas nuevas arbitrarias.
6. No cambies los 44 registros iniciales, sus contadores ni el servidor replay; no añadas CSS ni campos obligatorios al frontend.
