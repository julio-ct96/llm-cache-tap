# 2.01 Decodificar y proyectar el protocolo Responses WebSocket

**Objetivo:** Convertir mensajes de la conexión a peticiones y eventos inspeccionables sin conservar el sobre de transporte.

**Lee:** `cachetap/request_body.py`: `parse` y validación; `cachetap/response_body.py`: `usage_events`, `output_text`; `tests/fixtures/copilot_responses_ws.json`; `tests/test_dependencies.py`: `ALLOWED`; `pyproject.toml`: mypy; `protocolo.md`: «Decodificación Responses WebSocket».

**Puedes tocar:** `cachetap/websocket.py` (nuevo), `tests/test_websocket.py` (nuevo), `tests/test_dependencies.py`, `pyproject.toml`.

## Pasos

1. Implementa `decode_client`, `decode_server` y `project_event` con las reglas y firmas del contrato. Usa tipos del módulo `record`; confina Any a la frontera del decoder, no a las funciones de estado.
2. Comprueba el tamaño cliente antes de decodificar. Valida UTF-8 estrictamente. Los ValueError usan motivos locales fijos y no incluyen payload ni excepciones del parser.
3. `decode_client` conserva solo la allowlist raíz del contrato y vuelve a validar el resultado con `request_body.parse`. No toca los objetos anidados de input/tools.
4. `project_event` construye objetos nuevos con los campos permitidos; no devuelve el evento original ni hace una copia superficial de todas sus claves. Aún no guardes estado ni conectes hooks.
5. Añade los siguientes tests:

   | Test | Entrada | Resultado esperado |
   | --- | --- | --- |
   | Petición real mínima | `client` del fixture serializado UTF-8 | Modelo, input, tools y reasoning conservados; `type` y `headers` ausentes |
   | Petición desconocida | Objeto con `type=ping` | None |
   | Frontera inválida | UTF-8 inválido, JSON roto, array, modelo numérico, input objeto, tools inválidas, previous_response_id numérico | ValueError sin contenido externo |
   | Bytes cliente | Mismo mensaje con máximo igual a su longitud / longitud menos uno | Aceptado / ValueError; medir UTF-8, no caracteres |
   | Proyección | Cada evento del fixture | Conservar únicamente las claves de la tabla del contrato; sentinel ausente de la proyección |
   | Uso y texto | Proyecciones del fixture convertidas con `builders.sse` | Uso y texto iguales a `expected` |
   | Eventos descartados | Razonamiento, tools, evento válido desconocido con headers | None |
   | Formas servidor inválidas | `type` no texto, delta numérico, response no objeto o usage no objeto cuando no es null | ValueError fijo |

6. Añade `websocket.py` a la tabla de imports permitidos con la fila del contrato y a la lista de mypy. Las funciones de esta tarea solo necesitan un subconjunto de esos imports; no añadas imports sin usar.
