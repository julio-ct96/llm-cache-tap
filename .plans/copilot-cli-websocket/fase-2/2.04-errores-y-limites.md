# 2.04 Completar errores, límites y desincronización

**Objetivo:** Que un problema de inspección no interrumpa al cliente ni produzca datos parciales engañosos.

**Lee:** `cachetap/websocket.py`: Session; `cachetap/capture.py`: limit, finish, fail; `cachetap/store.py`: reservas y clear; `tests/test_flows.py`: límites HTTP; `protocolo.md`: tabla completa de «Estado por conexión y límites».

**Puedes tocar:** `cachetap/websocket.py`, `tests/test_websocket.py`.

## Pasos

1. Completa todas las ramas de error de la tabla del contrato. Introduce un flag disabled por conexión; tras una situación ambigua se deja de inspeccionar hasta close, no se intenta recuperar adivinando el orden.
2. Usa mensajes locales fijos y sin datos externos para failed, incomplete, error, solapamiento, JSON/UTF-8 inválido y cierre. Añade `Session.uninspectable(at)` para el mensaje binario que señalará el hook.
3. Cuenta los bytes originales de cada mensaje servidor antes de decodificar. Si supera MAX_RESPONSE_BYTES, limita/finaliza en N/A inmediatamente sin invocar decode_server y deshabilita la conexión. El buffer SSE tiene además su límite independiente mediante capture.feed; si limita, finaliza y deshabilita igual.
4. Si start no obtuvo slot, finaliza N/A active_captures inmediatamente; deshabilita esa conexión y no acumules respuesta. Los slots siguen siendo los mismos de HTTP, no una segunda cuota de 16.
5. En cada entrada comprueba bajo LOCK si aún existe el registro activo. Si fue expulsado o limpiado, libera reserva/buffer sin publicar, loguear ni sumar coste, y deshabilita la conexión hasta close. No modifiques store.clear.
6. Añade estos casos, usando límites pequeños parcheados y TemporaryDirectory:

   | Caso | Resultado esperado |
   | --- | --- |
   | Failed, incomplete o error durante activa | ERR, sin uso/coste inventados, reserva liberada |
   | Dos creates solapados | ERR de la primera; no segunda fila ni atribución ambigua; disabled hasta close |
   | JSON/UTF-8 inválido servidor, o uninspectable durante activa | Mismo cierre prudente y sin texto externo en notas |
   | Create inválido o excesivo | Ninguna fila nueva; aviso fijo; disabled |
   | Mensaje al máximo exacto / un byte por encima | Aceptado / N/A response_size; el segundo no llama al decoder |
   | Payload multibyte | El límite usa bytes, no caracteres |
   | SSE retenido desborda sin superar bytes originales | N/A response_size, sin uso parcial |
   | Slots ocupados por capturas HTTP | N/A active_captures; no otro pool ni buffer creciente |
   | Clear o expulsión; siguiente evento y close | Sin resurrección, log/coste adicionales ni reserva/chunks |
   | Evento de conexión disabled | Sin nuevas filas, buffers, IDs retenidos ni contadores |
   | RuntimeError simulado en el procesamiento de una activa | La excepción original se propaga después de liberar reserva/chunks; no queda un éxito aparente |

7. En cualquier salida, incluidos errores inesperados propagados, libera reservas/buffers que pertenecen a la captura. No captures Exception para ocultar bugs; conserva los errores inesperados visibles después de la limpieza.
8. No añadas red ni hooks; el cableado solo se hace después de esta defensa.
