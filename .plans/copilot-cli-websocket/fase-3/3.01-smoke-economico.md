# 3.01 Preparar una comprobación real opt-in y económica

**Objetivo:** Disponer de un único comando acotado que valide Copilot contra el inspector sin tocar capturas del usuario.

**Lee:** `via.sh`, `start.sh`; `cachetap/config.py`: LOG y puertos; `tests/test_check.py`: pruebas de runner; `protocolo.md`: evidencia y coste no equivalente a factura. Consulta `copilot --help` y `copilot help environment` solo si el binario local existe: esos comandos no envían prompts.

**Puedes tocar:** `scripts/check_copilot.py` (nuevo), `tests/test_check_copilot.py` (nuevo).

## Pasos

1. Implementa un runner stdlib con CLI fijada: `--run-real` como opt-in obligatorio, `--copilot <ruta>` opcional. Sin opt-in imprime `READY: no model calls; use --run-real` y termina en 0 sin arrancar procesos ni conectar a proveedores.
2. Con opt-in, localiza copilot en el argumento, en PATH o en `~/.local/bin/copilot`, en ese orden. No uses la instalación npm antigua por ruta codificada, ni instales, actualices o autentiques nada.
3. Crea un TemporaryDirectory y dentro una carpeta vacía de trabajo, log métrico y bootstrap del addon. El bootstrap importa tap como addon, redirige config.DATA/LOG al temporal y usa el código actual del checkout. No copies ni persistas credenciales o cuerpos crudos.
4. Elige dos puertos libres con bind en 127.0.0.1:0 y rechaza 8899/8900. Libera las reservas justo antes de iniciar mitmdump; si hay carrera o no arranca, falla sin enviar el prompt. Usa la CA existente de `ca/`; si falta, explica el requisito y falla sin crear confianzas globales.
5. Espera al endpoint local `/api/reference` con deadline de 10 segundos. Usa el mismo venv, mitmdump y via.sh del proyecto; conserva autenticación del usuario sin leerla ni imprimir variables de entorno.
6. Envía exactamente un prompt `hola`, una sola ejecución del CLI. Configuración de la prueba:

   | Opción | Valor |
   | --- | --- |
   | Modelo | `auto` |
   | Perfil Auto | `efficiency` |
   | Directorio | Carpeta vacía temporal |
   | Instrucciones personalizadas | `--no-custom-instructions` |
   | Herramientas peligrosas | Deny de `shell`, `write`, `url`; no usar permisos allow-all/yolo |
   | MCP builtin | `--disable-builtin-mcps` |
   | Preguntas | `--no-ask-user` |
   | Updates, telemetría cliente y sincronización | Desactivados con las opciones verificadas en --help |
   | Logs y usage | Rutas temporales, log-level error, --usage-output-file |
   | Deadline del CLI | 90 segundos; terminar solo el grupo creado por el runner |

7. No presentes `--available-tools=` como garantía de ausencia de tools: en la prueba el CLI siguió enviando definiciones. No concedas permisos para resolver un error. No hagas reintentos, continuaciones, resúmenes ni segundo prompt si falla. No cambies COPILOT_HOME: se necesita la autenticación existente; el CLI puede guardar su sesión habitual en su propio directorio, que no se borra ni se lee para buscar secretos. El aislamiento del runner cubre workspace, métricas del inspector y puertos, no todo el estado interno del CLI.
8. Lee el snapshot y el detalle del registro por HTTP local sin proxy. Exige una fila WebSocket terminada con modelo explícito y usage; compara contadores read/write/output con el fichero usage del CLI, y input_total con sus métricas de modelo. No compares factura de créditos con cost.usd ni exijas HIT.
9. Exige que las métricas del CLI indiquen una única petición del modelo; si aparecen adicionales, informa y falla, sin repetir. Esta comprobación detecta desviaciones, no es un límite duro de facturación. No prometas que hola reduce el prompt de sistema ni que max-ai-credits permita un cap menor a los 30 créditos que admite la versión observada.
10. En finally para el CLI si sigue activo, después mitmdump, y elimina solo el temporal creado por el runner. No mates procesos ajenos, no abras el navegador y no limpies las capturas del usuario.
11. Añade tests unitarios con procesos/HTTP/reloj simulados: default sin I/O, binario o CA ausentes, proxy no listo, timeout CLI, cero registros, más de una petición, usage distinto y éxito. Comprueba un solo lanzamiento con prompt y la limpieza en todos los fallos.
