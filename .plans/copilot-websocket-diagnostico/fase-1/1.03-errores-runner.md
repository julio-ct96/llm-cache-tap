# 1.03 Mostrar el fallo saneado antes de limpiar los temporales

**Objetivo:** que un fallo de validación del registro sea diagnosticable sin filtrar contenido ni cambiar el número de llamadas.

**Lee:** `contrato.md`, secciones 2 y 4; `scripts/check_copilot.py` entero; `tests/test_check_copilot.py` entero.

**Puedes tocar:** `scripts/check_copilot.py`, `tests/test_check_copilot.py` y tu fila del índice.

## Pasos

1. Añade el formateador puro format_record_failure y sus validadores/tipos locales del contrato. No importes la aplicación ni examines stdout/stderr del CLI. No crees un framework de logging.
2. En la rama de decode_completed_record que hoy rechaza transporte/status/state añade el JSON saneado al error, conservando el prefijo actual. Las comprobaciones de ID anteriores permanecen iguales. No conviertas ERR en un veredicto aceptado de éxito.
3. Implementa límites, enums, códigos de notas, sustituciones y eliminación de claves ajenas según contrato 4. Nunca `str()` o serialización directa de objetos externos para depurar.
4. Extiende los fakes para poder pasar un registro fallido completo a run_real. Verifica una sola invocación con hola y limpieza de ambos grupos/temporales también al fallar por estado del registro.
5. Añade la tabla de regresiones:

| Entrada | Resultado esperado |
| --- | --- |
| Registro error/101/websocket y nota de solapamiento | RunnerError con reason=overlap, state=error y verdict=ERR; no éxito |
| Nota de cierre prematuro | reason=closed_before_completed |
| Error con diagnóstico válido | JSON reconstruido, enums y booleanos preservados |
| Diagnóstico ausente o inválido, lista de 33 pasos o contador booleano/256 | ws_diagnostic=null, sin volcar datos |
| Estados, notas, cabeceras, IDs y claves ajenas con sentinelas | Ningún sentinel en stderr ni en el mensaje de RunnerError |
| status=true o cadena | status=null, sin confundir booleanos con 101 |
| Valores desconocidos | unknown/null; nunca texto externo |
| Campo válido con claves ajenas | Solo claves permitidas en salida |
| Default sin --run-real | READY exacto, sin procesos ni HTTP |
| Éxito, COLD, métricas espejo y créditos opcionales | Mismo resultado validado de los tests actuales |

6. Comprueba el máximo de 8192 bytes y que el diagnóstico no se escribe a disco. No añadas retención de temporales, retries, opciones de modelo o llamadas reales.

- `venv/bin/python scripts/check_copilot.py` imprime exactamente `READY: no model calls; use --run-real`.
- RUNNER-TYPES, RUNNER-LINT, RUNNER-FORMAT, CHECK y PLAN-CHECK pasan.
- `git diff --check` pasa. No se ejecutó el CLI ni --run-real.
