# 1.01 Fijar las ambigüedades actuales sin cambiar producción

**Objetivo:** tener una matriz reproducible que demuestre que la misma nota de error no identifica una causa única.

**Lee:** `casos.json` y `evidencia.md` de este plan; `tests/test_websocket.py`: setup/teardown y helpers de WebSocketSessionTests, tests de secuencia, terminal duplicado, ID distinto y solapamiento; `cachetap/websocket.py`: Session.client, Session._process_server_message y Session.close; `tests/replay/adapter.py`: reset.

**Puedes tocar:** `tests/fixtures/copilot_ws_diagnosis.json` (nuevo), `tests/test_websocket_diagnosis.py` (nuevo) y tu fila del índice.

## Pasos

1. Copia el manifiesto `casos.json` al nuevo fixture. Los tests leen solo el fixture bajo `tests`, nunca `.plans`. El fixture original permanece intacto y es la fuente de mensajes artificiales.
2. Implementa un ejecutor pequeño de las siete secuencias: create/created/completed del fixture original; wrong_completed cambia únicamente el ID por otro artificial; create_generate_false añade únicamente el booleano false; close llama Session.close. Usa timestamps sintéticos crecientes, copias independientes y log temporal. No arranques proxy, navegador o CLI.
3. Para cada caso comprueba estados, veredictos, nota de error, reservas y conexión deshabilitada contra esta matriz ya ejecutada:

| Caso | Estados | Veredictos | Reservas antes de limpiar | Deshabilitada |
| --- | --- | --- | --- | --- |
| sequential | done, streaming | PARTIAL, ausente | 1 | no |
| create_before_created | error | ERR | 0 | sí |
| created_then_create | error | ERR | 0 | sí |
| completed_without_created | error | ERR | 0 | sí |
| mismatched_completed | error | ERR | 0 | sí |
| generate_false_then_create | error | ERR | 0 | sí |
| close_before_completed | error | ERR | 0 | sí |

4. En los cinco casos de solapamiento exige la nota exacta del manifiesto. En cierre exige su nota distinta. En errores exige ausencia de usage/cost, cero acumulados y cero líneas de log de finalización. No compares todo el registro: después se añadirá un diagnóstico opcional sin alterar estos resultados.
5. Comprueba que cerrar al final de cada caso deja cero reservas y restaura el estado del test. Fija expresamente que decode_client sigue eliminando generate del cuerpo normalizado; no presentes ese test como tráfico real observado.
