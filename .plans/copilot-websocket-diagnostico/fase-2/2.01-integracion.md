# 2.01 Verificar el diagnóstico desde hooks, API y runner sin proveedores

**Objetivo:** demostrar que un error sintético generado por los hooks se puede diagnosticar por la API sin filtrar la traza a SSE o JSONL.

**Lee:** `contrato.md`, secciones 2–4; `tests/test_websocket_hooks.py` entero; `tests/test_websocket_dashboard.py` entero; `cachetap/dashboard.py`: do_GET y _events; `cachetap/store.py`: push y append_log; `scripts/check_copilot.py`: decode_completed_record y format_record_failure.

**Puedes tocar:** `tests/test_websocket_hooks.py`, `tests/test_websocket_dashboard.py` y tu fila del índice. No cambies producción ni la UI.

## Pasos

1. Añade a los tests de hooks dos intercambios artificiales: create/created/segundo create, y create/created/cierre. Usa objetos mitmproxy reales y los helpers de no mutación existentes.
2. Exige estado error, nota correcta y diagnóstico con overlap o close; los mensajes, flags y cada elemento del historial siguen idénticos. Dos conexiones no comparten pasos ni contadores.
3. Amplía los tests de dashboard para generar ambos errores mediante hooks y leer GET /api/record/<id> en servidor propio con puerto 0 y log temporal. No construyas un Record artificial que evite el pipeline.
4. Comprueba las superficies:

| Superficie | Resultado |
| --- | --- |
| API de detalle | ws_diagnostic presente y conforme al contrato |
| SSE terminal y snapshot | ws_diagnostic ausente; estado y nota siguen visibles |
| JSONL temporal | Sin ws_diagnostic ni contenido sensible; errores no inventan líneas de finalización |
| Body | Sobre headers eliminado; no se le inserta el diagnóstico |
| Reservas y conversación | Cero reservas tras error; ningún coste inventado |
| Formatter del runner sobre el JSON real de la API | Categoría correcta; sin IDs, input, cabeceras, output ni razonamiento |

5. Invoca el decoder/formateador del runner solo como función local; no ejecutes run_real ni un proceso Copilot. En el caso correcto original, conserva el test completo de usage y coste y exige ausencia de ws_diagnostic.
6. Cierra conexiones, suscriptores y servidor aun si falla una aserción. No uses esperas sin límite ni timeouts dependientes del proveedor.

- FULL, RUNNER-TYPES y PLAN-CHECK pasan.
- `git diff --check` pasa. No se cambiaron contratos de HTTP ni el golden.
