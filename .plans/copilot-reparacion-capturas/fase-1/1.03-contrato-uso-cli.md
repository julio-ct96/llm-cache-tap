# 1.03 Fijar el contrato de uso sin inventar el JSON perdido

**Objetivo:** Determinar las variantes de uso demostrables del CLI y fijar offline qué exige hoy el validador.

**Lee:** `evidencia.md`, sección Uso CLI; `scripts/check_copilot.py::ModelUsage`, `TokenDetails`, `_model_metrics`, `_decode_token_count`, `decode_cli_usage`, `compare_usage`, `read_cli_usage`; `tests/test_check_copilot.py::model_row`, `cli_usage`, `test_unknown_cli_usage_schema_fails_without_guessing`, tests de contradicciones y mirrors.

**Puedes tocar:** `contratos/uso-cli.json`, `contratos/uso-cli.md` (nuevo), `tests/test_copilot_usage_contract.py` (nuevo). Además, solo tu fila del índice.

## Pasos

1. Ejecuta BASELINE antes de investigar. No leas `data/` para intentar recuperar un temporal ya eliminado.
2. En un test nuevo, usa copias del constructor `cli_usage` existente. Fija estos resultados del lector actual; marca expresamente los casos ausentes como sintéticos, no como muestras Gemini/Grok:

   | Modificación de la entrada válida | Resultado actual |
   | --- | --- |
   | Ninguna | Se acepta y conserva los contadores |
   | Eliminar usage.reasoningTokens | RunnerError |
   | Eliminar tokenDetails.cache_write | RunnerError |
   | Eliminar tokenDetails entero | RunnerError |
   | Mirrors de la entrada válida | No añaden peticiones al conteo |

3. Busca el contrato en fuentes públicas oficiales o código de CLI/SDK de versión acreditada aplicable a 1.0.105. Documenta cada ruta de campo, forma, unidades, opcionalidad y semántica. No derives opcionalidad del uso HTTP del panel, del nombre del proveedor ni de los tres tests sintéticos.
4. Crea `contratos/uso-cli.md` con secciones `Fuentes`, `Esquema demostrado`, `Rechazo observado`, `Ausencias y contradicciones`, `Decisión`. Escribe literalmente que el campo rechazado en las dos pruebas históricas no se conservó. Si solo se puede demostrar un formato válido pero no atribuirlo a esos fallos, distingue ambas conclusiones.
5. Actualiza el JSON: `sources` con ubicación/versión/afirmación/limitación; `decision` con campos que se pueden admitir sin estimar; `unknowns` con lo no resuelto. Mantén `approved=false`. Usa `status=insuficiente` cuando falte evidencia para la modificación propuesta; no rellenes con defaults ni intentes recuperar valores de mirrors.
6. Entrega al orquestador para preparar 2.02. No cambies el lector ni `compare_usage` en esta tarea. No amplíes el smoke runner a HTTP, Auto ni nuevas invocaciones reales.
