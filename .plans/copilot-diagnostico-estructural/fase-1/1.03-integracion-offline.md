# 1.03 Integración offline y privacidad

**Objetivo:** demostrar que los ordinales llegan al detalle/JSON sanitizado y que no se filtran a SSE, snapshot, body ni JSONL.

**Lee:** `contrato.md`, secciones 1–2; `tests/test_websocket_hooks.py::test_overlap_and_close_diagnostics_are_isolated_and_do_not_mutate_messages`; `tests/test_websocket_dashboard.py::test_hook_failures_are_diagnosable_only_from_api_detail`; `cachetap/dashboard.py::Handler.do_GET`, `_events`; `cachetap/store.py::push`, `append_log`; `scripts/check_copilot.py::format_record_failure`.

**Puedes tocar:** `tests/test_websocket_hooks.py`, `tests/test_websocket_dashboard.py` y tu fila de `README.md`. Sin cambios de producción/UI/golden.

## Pasos

1. Usa hooks reales de mitmproxy de prueba y servidor HTTP de puerto efímero; no fabriques registros ni uses tráfico real. Añade IDs centinela en fallos sintéticos.
2. Comprueba el pipeline:

   | Superficie | Esperado |
   | --- | --- |
   | `GET /api/record/<id>` en fallo | `ws_diagnostic` con símbolos, sin IDs wire. |
   | Runner JSON de ese detalle | símbolos allowlisted; sin claves/modelos/valores externos. |
   | SSE terminal y snapshot | Estado/nota sí; `ws_diagnostic` e `id_symbol` no. |
   | `GET /api/body/<id>` | No diagnóstico, headers ni sentinels. |
   | JSONL temporal | No diagnóstico, `output`, IDs ni sentinels. |
   | Reserva/coste | Limpieza igual; error no inventa usage/cost. |

3. Mantén cleanup de sesión, suscriptores y servidor. No leer panel de usuario, `data/`, ni usar puertos 8899/8900.
