# 1.04a Preparación local del harness, sin inferencias

**Objetivo:** adaptar mecánicamente el harness anterior para conservar evidencia estructural suficiente, sin ejecutarlo contra modelos todavía.

**Lee:** estas instrucciones y reglas; el orquestador proporciona `ORIGINAL` y la ruta exacta del harness anterior. De ese directorio lee únicamente `run_one.py` y `plan.json`, no resultados ni configuración privada. De `scripts/check_copilot.py` lee `SchemaError`, `format_schema_diagnostic`, `read_cli_usage`, `format_record_failure` y cleanup de procesos. Consulta solo tu fila del índice.

**Puedes tocar:** un nuevo directorio exclusivo dentro de `ORIGINAL/data/model-checks/`, solo `run_one.py`, `plan.json`, `offline_check.py` y artefactos sintéticos de su comprobación; tu fila del índice. No modificar el harness ni evidencia anteriores, código del repo ni otros documentos. Mantén permisos 0700/0600. Ningún artefacto privado entra en Git.

## Receta cerrada

1. Crea un directorio con `mkdtemp`, prefijo `structural-low-`, bajo la raíz de evidencia indicada. Copia el harness anterior allí y conserva su raíz `HERE.parents[2]`.
2. Plan de cinco invocaciones máximas, sin Auto, esfuerzo `low`, límite de sesión 30 AI credits (no prueba de gasto ni garantía por petición): `gpt-6.1-terra`/`hola`; `claude-opus-5.5`/`que tal`; `gemini-4-argon`/`buenas`; `grok-4.7`/`hola`; `mai-code-1.1-flash`/`que tal`. Nombres únicos: `openai-low`, `anthropic-low`, `google-low`, `xai-low`, `microsoft-low`.
3. Conserva los flags del harness anterior, timeout 60 s, directorio de trabajo temporal vacío, denegación de herramientas, `--no-auto-update`, proceso en sesión propia y cleanup solo de ese grupo. Un directorio de resultado existente bloquea una segunda invocación. Ningún bucle vuelve a llamar al CLI.
4. Antes de borrar el temporal de uso, intenta el decoder estricto. Captura `SchemaError` y guarda `cli_usage_validation=invalid_schema` y `cli_usage_diagnostic=format_schema_diagnostic(error)` reconstruido desde allowlists. Otros errores de lectura conservan categoría fija, nunca texto dinámico. No relajar campos ni guardar JSON bruto.
5. Del JSON temporal válido como JSON, guarda una proyección independiente SOLO de la entrada cuyo nombre coincide exactamente con el modelo solicitado: tipos/presencia de `requests`, `usage`, `tokenDetails` y sus campos conocidos; números enteros no negativos para contadores de requests y tokens conocidos, y `totalNanoAiu` si válido. Ningún nombre de clave/modelo externo, ID, mirror, valor string, cuerpo o dato desconocido. Si hay otros modelos, solo número de entradas y suma de request counts válidos, sin nombres. Esta proyección no sustituye al decoder estricto ni autoriza costes; marca siempre su validación por separado. Missing y null deben distinguirse. La evidencia de un campo rechazado es ruta/tipo, no su valor.
6. Conserva prompts sintéticos, respuesta final del asistente proyectada (máximo 4096 caracteres y truncado indicado), métricas permitidas y diagnóstico WS sanitizado. No retener stdout/stderr/eventos crudos, razonamiento, headers ni cuerpos de sistema. No imprimir respuestas/errores crudos. `automatic_retries_harness=0`, `cli_internal_retries=not_controlled`; contadores observados permiten detectar multiplicidad, no probar causas.
7. Guarda snapshot ligero antes/después, nunca detalles brutos. Para cada registro nuevo conserva solo el mismo conjunto explícito de métricas del harness anterior y diagnóstico sanitizado. Lee el body solo para comprobar esfuerzo `low` y último mensaje user igual al saludo sintético; guarda únicamente esos booleanos, no el body. Atribución por ventana no prueba causalidad: marca ambigüedad si no hay exactamente una fila del modelo solicitado, aparece otro modelo o CLI cuenta más de una petición. No convertir una captura ERR o schema inválido esperado en retry.
8. Cada resultado declara `continue_campaign`: false ante fallo CLI/timeout, ausencia o ambigüedad de atribución, contadores que prueben más de una petición; true puede conservar ERR/invalid_schema como evidencia pendiente, nunca como captura reparada. El orquestador decide cada invocación siguiente, sin batch automático. Cualquier validación de prompt/effort falsa detiene la campaña.
9. Añade `offline_check.py` con mocks de red, snapshot y Popen/cleanup. Ejecutarlo NO llama al CLI ni conecta a puertos. Fija: argv contiene exactamente saludo/low/modelo; una invocación por nombre; segunda bloqueada antes de Popen; datos centinela no aparecen en proyecciones; missing/null y bool correctos; schema inválido conserva ruta/tipo; respuesta proyectada guardada; timeout/fallo/multiplicidad detienen campaña. La muestra simulada de API usa solo datos sintéticos.

## Verificación

- Devuelve ruta local, hashes de tres ficheros, pruebas y API del harness. No ejecutas modelo, no recargas, no consultes el panel vivo y no hagas Git add/commit/push.
